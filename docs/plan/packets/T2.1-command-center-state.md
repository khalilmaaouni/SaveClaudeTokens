## The six tests, by exact name

Put them in `scripts/test_tools.py`, matching the fixture style already used
there. The first two are named in the WBS and are the done-check; the other
four come from the memo and cover what reading the source turned up.

1. `test_state_proving_beats_opportunity`: an open experiment and a firing
   recommendation together render PROVING.
2. `test_state_healthy_when_do_nothing`: no experiment, `do_nothing` True, no
   verified rows.
3. `test_state_unreadable_baseline_still_proving`: `list_open_experiments`
   returns `[{"_unreadable": "/some/path.json"}]` with no `label` key. PROVING
   renders, the reason names the path, and nothing raises.
4. `test_state_all_triggers_insufficient_is_no_data`: every strategy trigger is
   insufficient, so `do_nothing` is True for lack of data. NO DATA renders,
   never HEALTHY.
5. `test_state_historical_verified_does_not_beat_healthy`: the only VERIFIED row
   carries `historical` True. HEALTHY renders.
6. `test_state_opportunity_beats_verified`: a firing recommendation and a non
   historical verified row together render OPPORTUNITY.
7. `test_state_unrecognised_format_beats_proving`: `parse_health="UNRECOGNISED"`
   with an open experiment AND a non historical verified row present still
   renders NO DATA. Read section 2a of the memo before writing this one. It is
   the test that proves the product refuses to be confident on a meter that
   cannot read its own input.
8. `test_state_parse_health_none_is_unchanged`: the default argument changes no
   existing behaviour, asserted against the same fixtures as tests 6 and 7.

The signature is `command_center_state(..., parse_health=None)`. `None` means
unknown and must preserve today's behaviour exactly. The string `UNRECOGNISED`
returns NO DATA ahead of every other rule, PROVING included. Nothing in the
codebase passes anything but `None` yet: the format canary that would supply it
is a separate task that does not exist. Do NOT build that canary here.
