# Token Shield: website brief (for the founder's site build)

Distilled 2026-08-14 from the standalone blueprint, filtered through the shipped product's honesty rules. Everything here is buildable copy; nothing promises a number we have not measured.

## Hero

Headline: Your AI coding agent is leaking tokens. Find the leak. Fix the right leak. Prove it.

Subhead: Token Shield measures where your Claude Code tokens actually go, tells you which fix (including none) deserves to run on YOUR workload, and proves the result with labeled evidence. Free, open source, local-first.

Primary CTA: Install Token Shield. Secondary CTA: See how proof works.

Trust strip: Local-first. No cloud required. Zero hooks by default. Real usage counters. No universal savings claim.

## The five-second story (section order for the page)

1. Your agent wastes tokens in different ways; yours are not the average.
2. Token Shield measures which waste is actually yours (MEASURED, from your own transcripts).
3. It recommends the smallest treatment that fits, native first, a specialist plugin only when it earns its place, and do-nothing when that is the honest answer.
4. An experiment proves whether the fix worked (VERIFIED) or says NOT_PROVEN plainly.
5. When your stack changes, old proof is demoted to HISTORICAL and revalidated, never silently inherited.

## Sections that differentiate us (each one is already true in the product)

- We start every savings number at zero. A compression ratio is not a saving; an external benchmark is not your saving. Labels never blend: VERIFIED, MEASURED, ESTIMATED, NATIVE, DECLARED, NO DATA.
- The best optimizer sometimes does nothing. Do-nothing is a first-class recommendation with the math shown.
- A smaller payload is not automatically a saving. We measure the whole task, not the squeezed log.
- Every optimizer is a treatment. Ponytail, caveman, token-saver, RTK, context tools: Token Shield diagnoses, prescribes, measures, and keeps or rolls back. Honest comparison page: "only terse answers? Caveman may be enough" builds more trust than a green-checkmark table.
- Your repository is not our dataset. Code, prompts, transcripts stay local; the doctor answers "what leaves this machine" exactly.
- NOT_PROVEN is the product working. Show the real verdict screenshots, including the one that refused to claim.

## What NOT to publish

- No "save 65%" style universal percentage, ever, unless a scoped benchmark is attached to that exact workload.
- No self-scored capability tables.
- No claims for companions that failed first-party curation.
- Savings shown per label; regressions shown negative; NO DATA beats a guess.
