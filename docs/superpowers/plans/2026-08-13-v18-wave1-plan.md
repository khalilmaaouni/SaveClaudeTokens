## Scope, wave 1 only

In scope (docs/ROADMAP.md, "Adopted direction" section, the wave 1 bullet):
- data/companions.json schema v2: tested version ranges, hook footprints, curated activation and rollback commands, last_reviewed dates.
- Native discovery through Claude Code's own plugin inventory, captured as CLAUDE PROJECTED, never as a saving.
- A local companion state file.
- A read-only ecosystem doctor: health, overlap, and conflict report.

Out of scope, explicitly deferred to wave 2 (docs/ROADMAP.md, wave 2 bullet): data/compatibility.json, a hook ownership table, overlap detection that suppresses the advisor's own duplicate cards, and suppression memory/cooldowns for rejected or failed treatments. Wave 1's doctor may report a raw shared-hook fact in plain text; it must never suppress or auto-adjust an advisor card, and it must say plainly that judging which overlap actually matters is a wave 2 feature it does not yet have.

Out of scope, explicitly deferred to v1.9: the companion adapter layer (scripts/companions/), mode guidance, guided install/rollback recipes, the marginal attribution waterfall on the dashboard.

## Adopted principles, binding on every step below (docs/ROADMAP.md, verbatim in substance)

- Prescribed, never bundled: no companion becomes a plugin dependency; this wave adds visibility only, never an install action taken on the user's behalf.
- Capability first, brand second: the doctor names what is missing, not just which companion is missing.
- Telemetry hooks stay silent: nothing built in this wave prints advice on its own; every module here runs only when the user runs a command.
- External evidence never populates the user's savings: discovery output carries a token number in no field that feeds the ledger; it is never written to the experiment ledger, never summed into OPPORTUNITY or VERIFIED, and its confidence label is CLAUDE PROJECTED, a label distinct from MEASURED, ESTIMATED, VERIFIED, and NATIVE.

Two things this evidence settles, that the plan no longer needs to guess at:

1. The CLI's own section header is literally "Projected token cost." docs/ROADMAP.md's phrase "captured as CLAUDE PROJECTED" is a direct label on this exact feature, not a loose analogy. Discovery in Step 3 should treat this section as the CLAUDE PROJECTED source, and nowhere else.
2. `SessionStart` is registered by all three currently curated companions. A doctor that flags every shared-hook pair as a "conflict" would fire on `SessionStart` constantly and teach the user to ignore it, the same failure mode the roadmap's "telemetry hooks stay silent" principle warns against, just applied to Token Shield's own output instead of a companion's. Step 5 below reports every shared hook as a plain fact, with no severity judgment attached, and says outright that judging which overlap matters is wave 2's job (the hook ownership table), rather than inventing a severity rule here that no source confirms.

Residual, still-open risk: `plugin details` output is plain text with no schema guarantee. A future CLI release could reword the "Hooks (" line or the "Always-on:" line and silently break a naive parser. Step 3's parser must fail to NO DATA on an unrecognized shape, never crash, never guess a number.

### Step 3: discovery module

File: `/Users/khalil.maaouni/SaveClaudeTokens/scripts/discover_companions.py` (new file)

Function `discover()`: calls `claude plugin list --json` via `subprocess.run` (stdlib only, no new dependency), parses the confirmed JSON array shape from the evidence above into `{"name": <id split on "@">, "enabled": ..., "source_label": "CLAUDE PROJECTED"}` per entry. The string `"CLAUDE PROJECTED"` is literal and appears on every entry; no entry in this module ever carries a token count, a dollar figure, or any of MEASURED/ESTIMATED/VERIFIED/NATIVE.

Function `hook_footprint_of(name)`: calls `claude plugin details <name>` and parses the "Hooks (" line from its plain text output (confirmed format quoted above) into a list of hook event names. On any line that does not match the expected "Hooks (N)  <comma-separated names>" shape, return `None` (NO DATA), never raise, never guess. This is read-only, on-demand data, kept separate from the curated `hook_footprint` already hand-entered in Step 1's data/companions.json, since a live discovery run can disagree with the curated snapshot if a companion changed its hooks since `last_reviewed`, and that disagreement is itself useful information for the doctor in Step 5.

Never raises: wrap both subprocess calls the same way `load_companions()` in `scripts/token_shield.py` wraps `json.load` (`try`/`except` catching `OSError`, `subprocess.CalledProcessError`, and a JSON decode error), returning `None` on any failure rather than raising, matching this repo's existing defensive pattern.

Function `write_state(discovered, path)`: writes the local companion state file (see Step 4) via plain `json.dump`, stdlib only. Fold this into the same module rather than a second file, there is not enough logic here to justify a separate one.

None of these functions run from a hook. This module only runs when a human runs it directly or via the doctor in Step 5.
